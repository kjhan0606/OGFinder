# Licensing rules for Astrafex Web (commercial use)

Decision of the owner (2026-10-04): the web version must be **commercially usable**.  These rules are binding for every change.
They are engineering rules, not legal advice; the final licence of this repository is **still to be decided by the owner**
(`LICENSE` is a proprietary placeholder).  Background audit of the desktop tree: `OGFinder/docs/license_audit.md`.

## R1 - Original code and permissive dependencies only

* All code in `server/`, `web/src/`, `tools/` is written for this project (by the owner; no third-party source is included).  One module has a
  documented prior art in the owner's own OGFinder tree: `server/ds10core/toolspec.py` (command-template expander) implements the same
  template language and behaviour as OGFinder's `ogfkit/cliexpand.py` (same author); it was first a behavioural clone and has been rewritten from the
  documented manifest semantics, and `server/tests/test_job_parity.py` checks equal results against OGFinder's expander in a child process.  It is the
  only place where the project says "mirrors OGFinder"; the plugin manifests' schema is OGFinder's (read as data).  The DS9 region *file format* is
  supported as a public text format (parser and writer are our own; the writer's header lines are our own wording, not ds9's).  Do not copy or translate code from SAOImageDS9 / tksao / AST / funtools /
  XPA or any other GPL/AGPL/LGPL project, and do not use their data structures or algorithms by reading their source.  Implement from
  public standards (FITS 4.0, WCS Papers I-II: Greisen & Calabretta 2002, Calabretta & Greisen 2002) and from our own design
  (`OGFinder/docs/phase2_web_design.md`).
* Allowed dependency licences: MIT, BSD-2/3, Apache-2.0, ISC, PSF-2.0, HPND/MIT-CMU, Zlib, 0BSD, Unlicense/CC0, BlueOak, BSL-1.0, bzip2-1.0.6, Qhull;
  **MPL-2.0 where fine** (file-level copyleft: use unmodified, keep notices and source availability; `certifi` and the separately shipped, unmodified Pyodide runtime). BSL-1.0 and bzip2-1.0.6 are known permissive licences for Boost headers compiled into SciPy and the compression library linked into CPython; pinned texts and provenance are in the browser runtime review.
* Forbidden anywhere in the repository or its shipped (browser / WASM / server image) artefacts: GPL, AGPL, LGPL (also
  "LGPL with dynamic linking" - not without a separate written decision), SSPL, EUPL, non-commercial clauses, "unknown".
* The **application and worker JS bundles contain first-party code** (no runtime npm dependency; built from `web/src` only). Browser computation additionally ships unmodified, separately pinned JS/WASM/wheel runtime assets; see `docs/browser_runtime_licenses.md`.  Adding
  a runtime JS/WASM dependency needs: licence on the allowlist, an entry in `THIRD_PARTY_NOTICES.md`, and review of its transitive
  closure.

## R2 - Notices and the machine-checked allowlist

* `THIRD_PARTY_NOTICES.md` lists every Python and npm package (runtime and dev) with version and licence.  It is generated by
  `python tools/license_check.py --notices`; a test fails if it is out of date.
* `tools/license_check.py` + `tools/tests/test_licenses.py` run in CI (`scripts/ci.sh`, `ci/github-actions-ci.yml.example` - copy to `.github/workflows/` with a token that has the workflow scope): they **fail on
  GPL/AGPL/LGPL/SSPL/EUPL/non-commercial or unknown licences** in the transitive closure of `requirements.txt`,
  `requirements-tools.txt` (libraries of the tool processes: scipy, astropy, photutils, matplotlib), `requirements-dev.txt` and
  `web/package-lock.json`, check that the browser bundle contains only `web/src` inputs, and scan our
  own source for GPL headers or ds9 copyright strings.
* A dependency with missing metadata may be listed in `tools/license_overrides.json` **with a written reason**; that file is
  reviewed like code.
* `LICENSE`: "proprietary, all rights reserved - to be decided by owner" (placeholder).

## R3 - OGFinder / ogfkit only across a process or API boundary

* The web code never imports, links or bundles OGFinder code.  The server reads `plugins/*/plugin.json` as **data** (manifests) and, in
  later milestones, runs OGFinder tools as **separate processes** (CLI `argv` from the manifest) or over an HTTP API, in a sandbox.
  Nothing from `ogfkit` reaches the browser.
* Every tool is "server-only" until a local/WASM runtime exists (chapter 13 of the design).  `GET /api/v1/capabilities` and
  `docs/capability_table.md` flag every tool that imports a copyleft or unknown-licence library or needs a non-redistributable binary
  as **"server-only, license review needed"**.  Currently flagged: `rebound`, `assist` (GPL-3.0+, used by the moving-object tools),
  `sep` (upstream LGPL-3.0 / BSD dual - confirm which applies), PyMuPDF (AGPL), `ds9_sextract` (SExtractor-derived), GALFIT
  (freeware, not redistributable), and libraries whose licence was not verified (`lenstronomy`, `prospect`, `pysersic`, ...).
  A flagged tool must not be enabled in a commercial deployment before the review is done; the UI shows the flag to the operator.
* **Enforced by the job runner (M3).**  `POST /api/v1/jobs` starts a tool only as a subprocess (own process group, minimal environment,
  private HOME/work directory, timeout, cancel = SIGTERM then SIGKILL of the group); `ogfkit`, `sep`, `rebound`, ... are never in the
  server's `sys.modules` (tested).  The policy is evaluated **per step**: the step's CLI script is scanned transitively through its local
  imports (try-guarded imports are reported as optional) plus the declared binaries; any module not on the known-permissive list, an
  unknown binary, or an unresolvable script makes the step *server-only, license review needed* and the API answers **403** unless the
  operator sets `ASTRAFEX_ALLOW_REVIEW_TOOLS=1`.  The default runnable set is the built-in detector (`ds10_detect`, original code),
  `isophote.fit` (photutils, BSD-3), `example_hello.greet` and the other steps listed under "Runs by default" in
  `docs/capability_table.md`.  The UI mirrors the same flag (disabled Run + badge), but the server is the authority.

## R4 - Data

* Tests and demos use **synthetic** data (`tools/make_sample_fits.py`) or commercially usable public data (HST/HUDF from MAST, SDSS
  with its image-use policy).  Real files are never committed (`*.fits` is git-ignored); local integration tests read them from a
  path given by the developer (`ASTRAFEX_SAMPLE_FITS`).
* **Gaia, DSS and GSC** products (CC BY-NC / commercial use prohibited) are not used in any shipped feature.  If a feature ever needs
  them it must carry a visible **restriction flag** (`data_restriction: "non-commercial"`) in the API and the UI and be off by default
  in commercial deployments.  The same applies to any survey whose terms are not checked.

## R5 - FITS, WCS, pyramid, viewer

* FITS parser, WCS (linear + TAN/SIN/ARC), tile pyramid, statistics and the WebGL viewer are **written from scratch** here.
* `astropy` (BSD-3-Clause) is allowed on the server and as an independent **test reference** (`requirements-dev.txt`); it is not
  needed by the shipped code path today.  Other permissive FITS/WCS libraries may be added under R1/R2.
* Not implemented (reported, never guessed): tile-compressed images, SIP/TPV distortion (flag `sip_ignored`), non-zenithal projections.

## Checklist for a pull request

1. No copied code; sources cited in comments are standards or papers only.
2. New dependency: licence on the allowlist, `python tools/license_check.py --notices` re-run, notices committed.
3. New OGFinder tool exposed: `GET /api/v1/capabilities` row reviewed; flags documented in `docs/capability_table.md`.
4. New sample data: synthetic or public with a commercial-use note in this file.
