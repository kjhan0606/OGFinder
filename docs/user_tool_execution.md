# 개인 분석도구: 등록·실행·파이프라인 편입

PIPELINE의 **사용자 도구 Import · 로컬 검증**에서 AI가 준비한 제출 폴더를
선택한다. 사전검사 결과를 검토하고 **내 브라우저 도구로 등록**을 누르면
도구 이름·설명·입력 파일·설정 JSON·실행 버튼이 생성된다. **실행 · 웹 로컬**을
누르면 해당 도구만 사용자 브라우저에서 실행하며 stdout/stderr와 결과 파일을
표시한다. 전체 서버/로컬 모드는 바뀌지 않는다.

`examples/user_tool_print/`는 단일 print 스크립트를 AI가 run 함수로 변환한
최소 예제다. 등록·실행하면 `ASTRAFEX_USER_PRINT_OK`가 로그에 표시된다.
`examples/user_tool_submission/`은 JSON 숫자 배열을 받아 평균 결과 JSON을 만든다.
둘 다 새 과학 알고리즘의 정확성 검증을 대체하지 않는다.

개인 도구 원본, 명세, 검사 보고서, 최근 입력·설정·로그·산출물은 이 사이트의
계정별 IndexedDB에 저장된다. 새로고침 후 카드와 최근 결과를 복원하며 저장된
입력으로 다시 실행할 수 있다. 실행 도중 페이지를 닫으면 계산은 계속되지 않는다.
현재 실행은 종료될 때 저장되므로 중단한 실행의 중간 산출물 복원은 제공하지 않는다.
원본 JSON 백업은 코드·명세만 포함한다. 데이터·산출물은 별도 보관해야 한다.
백업 복원도 다시 사전검사를 거치며, 등록 삭제는 해당 개인 도구 저장 항목을 지운다.

사용자 코드·선택한 입력은 서버에 전송하지 않는다. 앱과 분리된 opaque-origin
iframe/Worker에서 실행하며, 앱 저장소 접근과 HTTP 연결을 차단한다. 서버가
제공하는 것은 검토된 고정 런타임과 인터페이스다. 서버에 임의 패키지를 설치하거나
사용자 코드를 배포하는 API는 없다. 법적 면책이나 AI 승인 결과를 표시하지 않는다.

지원 범위는 Python 표준 라이브러리, 제출한 자체 Python 모듈, 고정 버전의
NumPy/SciPy다. 임의 wheel·native 바이너리는 아직 지원하지 않는다. UDG 검출 등
사용자 알고리즘은 이 실행 환경에 맞춰 adapter를 작성해야 한다. 등록된 개인
도구는 독립 카드 또는 공식 분석 순서도에 편입한 사용자 단계로 실행한다.
일반 서버 job으로 등록되지 않는다.

## Web: 공식 분석 순서도에 편입

1. 분석 목적(ICL, LSBG 등)을 선택하고 원하는 삽입 위치의 단계를 클릭한다.
2. 등록된 개인 도구 카드에서 **선택한 파이프라인 단계 뒤에 편입**을 누른다.
3. 좌측 순서도에 생성된 사용자 단계를 선택하여 파일·JSON 설정을 지정하고 실행한다.
4. 선행 단계의 성공한 산출물을 입력별 목록에서 선택하고 **선행 산출물을 로컬 입력으로 연결**한다.
   연결 시점의 파일 사본을 사용한다. 선행 결과가 바뀌면 다시 연결·실행해야 한다.
5. 결과를 확인하고 **검토 완료 → 다음**을 누른다. 성공은 과학적 타당성 승인과 다르다.

개인 단계는 도구 코드의 사본을 고정한다. 원래 등록 카드를 삭제하거나 새 버전으로
바꿔도 기존 단계가 바뀌지 않는다. 편입 해제는 해당 단계만 제거한다.
입력·설정 변경과 단계 메모, 진행 상태, 최근 실행 로그·산출물은 브라우저에 저장한다.
실행 중인 Python의 메모리 상태나 미완성 산출물은 재개하지 않는다.

**사용자 단계·입력·산출물 ZIP 저장**은 개인 코드·입력 사본·결과·진행을 저장한다.
공식 마지막 저장 단계의 ZIP 저장을 사용하면 기존 공식 세션 ZIP도 함께 포함한다.
**사용자 단계 포함 ZIP 복원**으로 복원하며 체크섬과 코드 해시를 확인한다.
Web 로컬 공식 산출물은 같은 로컬 모드에서 함께 복원할 수 있다. 서버 공식 job은
원래 서버의 계정·job 접근 권한이 필요하다. ZIP에 포함된 서버 세션은 기존 복원 경로를
사용한다. 사용자 단계 복원 자체는 코드를 실행하거나 서버에 업로드하지 않는다.
전체 실행 모드도 변경하지 않는다.

## Standalone: 개인 Python과 순서도

Tools → **User tool: register native Python…**에서 target이 `standalone` 또는
`both`인 제출 폴더를 등록한다. Tools → **User tool: add to selected pipeline**에서
도구를 고르면 현재 순서도 선택 단계 뒤에 편입한다. **선택 단계 입력·매개변수**에서
`inputs-json`에 논리 입력 이름과 로컬 파일 경로의 JSON 객체를, `params-json`에
설정을 입력한다. 선행 산출물도 그 로컬 경로를 명시하여 연결한다.
**선택 단계 도구 열기**가 실행을 시작한다. 각 실행은 별도 작업 폴더를 사용한다.

등록만으로 코드가 실행되지 않는다. 실행은 사용자의 로컬 Python과 사용자 권한을
사용한다. 이 네이티브 경로는 OS 보안 샌드박스가 아니며 명세의 권한 선언을 OS가
강제하는 구조가 아니다. 시간·메모리·파일 크기 제한, 별도 프로세스, 원본 해시 검사와
입출력 사본은 제공한다. 의존 패키지는 이미 설치된 정확한 버전만 사용하며 자동 설치나
임의 외부 바이너리 연결은 제공하지 않는다. Linux/macOS의 Python `resource`가 필요하다.

기본 등록 위치는 `~/.local/share/astrafex/user-tools`이며 `ASTRAFEX_USER_TOOLS`로
바꿀 수 있다. CLI는 `tools/user_tool_import.py --register DIR`,
`--run user_ID --work NEW_DIR --inputs-json '{"values":"/path/values.json"}'`이다.
등록 버전, 결과 보고서·로그·선언 산출물과 실제 실행 입력 사본을 연구 세션에 저장한다.
복원 시 저장된 코드를 재검증·재등록하고 입력 경로를 복원 사본에 연결한다.
등록 버전이 달라지면 기존 단계 실행을 막으며, 복원 또는 새 단계 편입이 필요하다.
복원은 사용자 adapter를 실행하지 않는다.

검증: 실제 CSP를 적용한 Chromium에서 print 등록·실행·재실행·새로고침 복원,
원본 백업·삭제·재검사·재등록, JSON 평균 산출물, 앱 저장소 및 HTTP 접근 거부,
취소·Python 예외·무한루프 시간 제한을 시험한다. 테스트 소스는
`e2e/test_personal_tool_execution.py`; 이전 검사 전용 회귀는 `e2e/test_user_tool_import.py`.

편입 회귀: `e2e/test_personal_pipeline.py`; Standalone은 `regression/test_personal_pipeline.py`와 기존 workflow 테스트를 사용한다.
